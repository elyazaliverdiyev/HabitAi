## Что нужно сделать (дважды: один файл SQL, один раз)

### Шаг 1. Открыть SQL Editor
1. Зайди на **https://supabase.com/dashboard/project/otvgzvzcwxffloeeyyiq/sql/new**
   (или: supabase.com → твой проект → слева «SQL Editor» → «New query»)
2. Откроется пустое поле для SQL-кода

### Шаг 2. Вставить и выполнить МИГРАЦИЮ
1. Открой файл: `C:\Users\JackV\Downloads\habitai\supabase\migrations\20260830120000_rls_security.sql`
2. Скопируй **всё содержимое** (Ctrl+A → Ctrl+C)
3. Вставь в SQL Editor (Ctrl+V)
4. Нажми зелёную кнопку **«Run»** (или Ctrl+Enter)
5. Внизу должно появиться «Success. No rows returned»

### Шаг 3. Проверить, что политики встали
1. Не закрывая редактор, очисти поле и вставь:
   ```sql
   SELECT policyname, cmd FROM pg_policies WHERE tablename = 'users';
   ```
2. Run → должна быть таблица с 4 политиками:
   - `users_select_own` (SELECT)
   - `users_update_own` (UPDATE)
   - `users_insert_own` (INSERT)
   - `users_leaderboard_read` (SELECT)

### Что делает эта миграция
| Блок | Эффект |
|---|---|
| Часть 1 | Колонки `asmaSrs` + `transformationJournal` → облачная синхронизация 99 Имён и Журнала заработает |
| Часть 2 | Удаляет старые «дырявые» политики (сейчас аноним может править чужие данные!) |
| Часть 3 | Новый принцип: каждый залогиненный видит/правит ТОЛЬКО свою строку (`auth.uid() = id`) |
| Часть 4 | Лидерборд остаётся рабочим: аноним видит только публичные профили (`"isPublic" = true`) |
